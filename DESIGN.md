# Backpressure Lab visual system

Backpressure Lab is now a **minimal black-first systems study**. The landing page is a quiet project brief, not a marketing dashboard: a plain header, one large thesis, one short explanation, one geometric pipeline diagram, and a single path into the experiment. The lab carries the same grammar into operation with hairline rules, measured whitespace, compact controls, and live data treated as the visual material.

The physical scene is an engineer reading a terminal-lit experiment late in a workday. Dark mode is the default: near-black canvas, warm off-white text, soft gray secondary copy, thin charcoal rules, and one muted brass signal for selection and offered load. Light mode is the same system inverted into a paper-white field, not a separate brand. Red is reserved for failure and overload; sage is reserved for healthy throughput.

Typography uses the loaded IBM Plex Sans variable family for headings and interface copy, with IBM Plex Mono only for measurements, states, IDs, and labels. Display type is large but lightly weighted, tracking never exceeds the system's readable range, and body copy stays short. There are no gradients, decorative textures, card stacks, glow effects, or ornamental metrics.

Navigation is deliberately small: landing anchors for Experiment, Model, and Source; a clear Overview path from the lab; and an icon-only theme control with an accessible label. Scenario selection is a row/grid of persistent buttons with selected state, not a dropdown. The same buttons work with a pointer, keyboard focus, and touch on narrow screens.

The landing diagram is crisp SVG geometry: a single flow line, four nodes, queue bars, and concise labels. The lab's charts are the proof: empty charts remain quiet until a real run produces lines; live pipeline stages, metrics, errors, and completion summaries retain the product's truthful concurrent behavior.

Motion has one authored first-viewport reveal, small interaction feedback, and live progress transitions. `prefers-reduced-motion` removes those transitions. The design's finish condition is simple: the visitor can explain where work waits, choose a condition, and start a real run without navigating a wall of UI.
